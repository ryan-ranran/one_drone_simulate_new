# D430i 双目与 IMU 标定：准备、录制和导入

## 1. 要准备的结果

| 项目文件 | 内容及来源 |
|---|---|
| `estimator_config.yaml` | OpenVINS 算法参数，项目导入工具基于模板生成；不由录包测出 |
| `kalibr_imucam_chain.yaml` | 左右相机、相机与 IMU 的几何关系及时间偏移，由 Kalibr 计算 |
| `kalibr_imu_chain.yaml` | IMU 白噪声、零偏随机游走、频率；需要噪声分析，导入工具整理 |
| `body.yaml` | 机体 FLU 坐标系到相机 IMU 的实际安装关系，需测量 |

采集三个包：（静止 IMU）、双目标定板、相机–IMU 运动标定板；另外测量机体安装。

## 3. 标定板和现场

准备与 Kalibr 兼容的 AprilGrid，打印后贴在**平整硬板**上，测量标签黑色边框
的实际边长和标签之间的实际间距；行列数量和 ID 排列必须与板文件一致。
打印时不要“适应页面”后仍照抄原尺寸。按实测数据填写 `aprilgrid.yaml`：

```yaml
target_type: aprilgrid
tagCols: <实际列数>
tagRows: <实际行数>
tagSize: <实测标签边长，单位米>
tagSpacing: <实测标签间距除以标签边长，无单位>
```

尖括号须替换为实测值。固定标定板，确保左右图都能清晰识别；运行时保持
与标定一致的设备、`image_rect_raw` 图流、分辨率和左右顺序。

## 4. 采集前检查

先检查是否已有 ROS 相机驱动：

```bash
pgrep -af 'ros2 launch realsense2_camera|realsense2_camera_node'
```

没有输出表示未发现这两个进程；有输出时，优先在原启动终端按 `Ctrl+C`，
确认退出后再启动。命令可能列出 launch 父进程和节点子进程；也应关闭
RealSense Viewer 等可能占用相机的程序，不要同时打开多个驱动。

终端 A 启动 RealSense。本机使用陀螺 200 Hz、加计 100 Hz、线性插值合并：

```bash
source /opt/ros/jazzy/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 launch realsense2_camera rs_launch.py \
  enable_color:=false enable_depth:=true \
  depth_module.depth_profile:=640x480x30 \
  enable_infra1:=true enable_infra2:=true \
  depth_module.infra_profile:=640x480x30 \
  depth_module.infra1_format:=Y8 depth_module.infra2_format:=Y8 \
  enable_gyro:=true enable_accel:=true \
  gyro_fps:=200 accel_fps:=100 unite_imu_method:=2
```

在另一个终端检查话题、频率、参数和剩余空间：

```bash
source /opt/ros/jazzy/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 topic list | grep -E 'infra[12]/image_rect_raw|imu|gyro/sample|accel/sample'
ros2 param get /camera/camera gyro_fps
ros2 param get /camera/camera accel_fps
ros2 param get /camera/camera unite_imu_method
ros2 topic hz /camera/camera/imu
# Ctrl+C 后，再分别检查两路图像
ros2 topic hz /camera/camera/infra1/image_rect_raw
ros2 topic hz /camera/camera/infra2/image_rect_raw
df -h "$HOME"
```

`ros2 topic hz` 每次等几秒后按 Ctrl+C。目标为组合 IMU 约 200 Hz、图像约
30 Hz；检查日志、长间隔及左右图像质量。关闭投影器：

```bash
ros2 param set /camera/camera depth_module.emitter_enabled 0
```

记录设备、固件、图像模式、频率和投影器状态。

### 录制时查看左右红外画面

保持终端 A 的相机驱动运行，在电脑的图形桌面**另开终端 C**：

```bash
source /opt/ros/jazzy/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 run rqt_image_view rqt_image_view /camera/camera/infra1/image_rect_raw
```

弹出的窗口显示左红外图；可在窗口上方的话题下拉框切换到
`/camera/camera/infra2/image_rect_raw` 查看右红外图。想同时看左右画面，
再开一个终端并运行：

```bash
source /opt/ros/jazzy/setup.bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 run rqt_image_view rqt_image_view /camera/camera/infra2/image_rect_raw
```

将两个窗口并排放置，然后在**终端 B**执行下面的 `ros2 bag record` 命令；
查看器订阅已有话题，不会启动第二个相机驱动。录制时确认两路都能看见清晰的
标签，大部分时间尽量看到整块板；移动到图像边缘时允许部分标签出画面，
无需每一帧都看全。相机–IMU 包要固定板、移动相机，不要只移动板。

若窗口无画面，先确认相机驱动仍在运行、话题名和两终端的 RMW / ROS domain
一致；运行 `ros2 topic info -v /camera/camera/infra1/image_rect_raw` 检查发布者及
QoS，必要时在查看器的 QoS 设置中匹配发布者。若提示找不到 `rqt_image_view`，
需要安装与当前 ROS 版本对应的查看器包；若没有图形桌面则需在有显示的电脑上查看。
查看器会增加系统负载；若录包出现丢消息、卡顿或断帧，先关闭查看窗口并检查
USB、磁盘及系统负载，待稳定后重录。



## 6. 正式数据采集

### 6.1 静止 IMU

整机静置、电机关闭，不碰桌面或拉动线缆。先分别确认以下话题有发布者和消息，
再开始录制：

```bash
ros2 topic info /camera/camera/imu
ros2 topic info /camera/camera/gyro/sample
ros2 topic info /camera/camera/accel/sample
ros2 bag record -s sqlite3 \
  -o ~/d430i_calibration/imu_static \
  --topics /camera/camera/imu \
           /camera/camera/gyro/sample \
           /camera/camera/accel/sample
```

结束后按 Ctrl+C，并用 `ros2 bag info ~/d430i_calibration/imu_static`
检查。[Kalibr IMU 噪声模型说明](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)
建议静置约 15–24 小时，再用 Allan 方差分析得到两种噪声密度和两种随机游走。
组合加速度计经过插值，200 Hz 输出不等于 200 Hz 独立原始加计样本。

### 6.2 双目标定板包

保持标定板固定、双目和 IMU 一起移动；录制时让板覆盖图像中心和四角，并有
不同距离、不同倾斜方向。动作平稳避免模糊，左右图都需看见足够多的标签。

```bash
ros2 bag record -s sqlite3 \
  -o ~/d430i_calibration/stereo \
  --topics /camera/camera/infra1/image_rect_raw \
           /camera/camera/infra2/image_rect_raw \
           /camera/camera/imu
```

结束后 Ctrl+C，检查 `ros2 bag info ~/d430i_calibration/stereo`、丢帧和图像。

### 6.3 相机–IMU 运动包

使用同一块固定板和相同驱动配置，录制一个新包。让双目始终能看到板，缓慢
改变位置并绕不同方向旋转、激励不同 IMU 轴，避免剧烈动作、模糊和遮挡。
无须启动电机，也不需要飞机飞行。

```bash
ros2 bag record -s sqlite3 \
  -o ~/d430i_calibration/imucam \
  --topics /camera/camera/infra1/image_rect_raw \
           /camera/camera/infra2/image_rect_raw \
           /camera/camera/imu
```

结束后检查 `ros2 bag info ~/d430i_calibration/imucam` 及日志。

## 7. 转换和运行 Kalibr

仅在包质量检查通过、已准备好对应 AprilGrid 配置和 IMU 噪声 YAML 后继续。
转换后的目标文件必须不存在：

```bash
~/d430i-calibration-venv/bin/rosbags-convert \
  --src ~/d430i_calibration/stereo --dst ~/d430i_calibration/stereo.bag
~/d430i-calibration-venv/bin/rosbags-convert \
  --src ~/d430i_calibration/imucam --dst ~/d430i_calibration/imucam.bag
```

转换后核对 ROS 1 bag 话题、计数及消息头时间戳；坐标、时间单位和图像编码
须保持一致。进入第 2 节中的容器，将真实的 `aprilgrid.yaml` 与 IMU 参数
文件放在宿主的 `~/d430i_calibration`，容器内对应 `/data`。
查看原始 ROS 2 包使用 `ros2 bag info ~/d430i_calibration/stereo`；查看
转换后的 ROS 1 `.bag` 则在容器内执行 `rosbag info /data/stereo.bag`。

IMU 输入文件 `imu.yaml` 必须填写实测或经过充分说明的值；话题对应录制数据：

```yaml
rostopic: /camera/camera/imu
update_rate: 200.0
gyroscope_noise_density: <分析结果>
gyroscope_random_walk: <分析结果>
accelerometer_noise_density: <分析结果>
accelerometer_random_walk: <分析结果>
```

`200.0` 仅在实际组合 IMU 为 200 Hz 且已验证时使用；所有尖括号必须替换为
实际结果。若暂用初值，只能标为台架实验，不是已完成标定。

容器内：

```bash
source /catkin_ws/devel/setup.bash
export MPLBACKEND=Agg
rosrun kalibr kalibr_calibrate_cameras \
  --bag /data/stereo.bag --target /data/aprilgrid.yaml \
  --models pinhole-radtan pinhole-radtan \
  --topics /camera/camera/infra1/image_rect_raw /camera/camera/infra2/image_rect_raw \
  --dont-show-report

rosrun kalibr kalibr_calibrate_imu_camera \
  --bag /data/imucam.bag --cam /data/stereo-camchain.yaml \
  --imu /data/imu.yaml --target /data/aprilgrid.yaml \
  --dont-show-report
```

本机双目标定使用 `--bag-freq 4` 时两目观测不连通；移除后成功。检查报告中的
重投影误差、覆盖范围、时间偏移和基线，并结合重复采集及已知距离验证。

## 8. 机体安装与导入

测量 `T_body_imu`：它把 IMU 光学坐标系的点转换到机体 FLU（前、左、上）
坐标系；平移单位为米，旋转需按相机实际朝向求出。飞机参考点的定义要一致。
相机换位置或方向后必须更新。不要抄另一架机体的 `body.yaml`。

硬件深度的安装变换也要核对。你的驱动报告 `depth_to_infra1` 为单位变换，
但仍需验证 frame、对齐模式和实际机体安装；其他模式可能需要提供实测
`T_body_depth`。硬件深度使用与图像对应的 `CameraInfo`。

获得检查通过的 IMU 参数、实际测量的 `body.yaml` 和 Kalibr 联合结果后，
在宿主机运行以下命令导入到一个**尚不存在**的输出目录：

```bash
cd ~/one_drone
python3 tools/import_kalibr.py \
  --camchain ~/d430i_calibration/imucam-camchain-imucam.yaml \
  --imu ~/d430i_calibration/imu.yaml \
  --body ~/d430i_calibration/body.yaml \
  --output ~/one_drone/deploy/calibration/d430i
```

本次实际导入命令见第 9 节。导入器拒绝覆盖已有目录，只检查配置结构，不保证
精度；它会将 Kalibr 的 `T_cam_imu` 取逆为 `T_imu_cam`。修改源文件不会自动
更新已导入文件，应导入新目录或更新生成文件。确认结果后设置 `launch.yaml`
的 `calibration_dir` 并重启，再检查静止漂移、位移尺度、回原点误差和点云方向。

## 9. 本次 D430i 标定记录及与 D435i 旧数据的比较

### 9.1 实际执行流程与文件

  `tagSpacing: 0.285714...`。
- `board_test` 约 27.4 秒，左右各 823 帧、IMU 5485 条；更早的一次 8.6 秒

- `stereo` 约 68.6 秒，左/右图 2061/2060 帧、IMU 13728 条。
- `imucam` 约 71.9 秒，左右各 2155 帧、IMU 14360 条。右图首帧时间戳早约

- `imu_static` 约 30 分钟，原始加计 181347 条、陀螺和组合 IMU 各 360590

### 9.2 相机和双目结果对照

| 项目 | 新：D430i（本次 Kalibr） | 旧：D435i（`uav1`） | 解读 |
|---|---:|---:|---|
| 图像 | 640×480，双目 `image_rect_raw` | 640×480，双目 `image_rect_raw` | 分辨率和图流名相同，不代表不同相机可共用内参 |
| cam0 `fx` | 395.857 px | 386.590 px | D430i 本次估值约高 2.4% |
| cam1 `fx` | 395.706 px | 387.039 px | D430i 本次估值约高 2.2% |
| 双目基线 | 50.0929 mm | 约 50.17 mm | 两者接近；D430i 驱动报告约 50.31 mm，可作交叉检查 |
| 平均重投影误差 | cam0 0.288 px，cam1 0.274 px（联合结果） | 当前 `uav1` 目录未附同口径原始报告 | 没有足够证据对新旧误差作定量优劣比较；D430i 结果仍需重复采集和实机验证 |

焦距和畸变系数是各自相机、图像处理链、采集数据与优化结果的属性。新旧焦距
存在约 2% 的差异，不应简单解释为 D430i 更好或更差，也不能把 D435i 内参复制
给 D430i。相机参数应与 Kalibr 使用的图流、分辨率、镜头顺序和图像几何保持一致。

### 9.3 相机–IMU、IMU 和机体安装差异

| 项目 | 新：D430i 导入结果 | 旧：D435i `uav1` | 结论 |
|---|---|---|---|
| cam0/cam1 顺序 | infra1 / infra2 | 项目内部 cam0 / cam1 | D430i 输入 Kalibr 时是 infra1 / infra2；运行时必须维持该顺序 |
| `timeshift_cam_imu` | cam0 +2.514 ms；cam1 +2.474 ms | cam0 −2.702 ms；cam1 −2.649 ms | 符号和数值不同；两目差值均小于导入器的 2 ms 一致性检查。不可复制旧偏移 |
| 相机–IMU 外参 | 本次联合标定估计，已由导入器取逆写入 `T_imu_cam` | D435i 自己的联合标定结果 | 外参依赖设备和安装坐标，不能跨相机直接沿用 |
| IMU 噪声密度 / 随机游走 | 与临时文件相同：gyro density `0.000232`、gyro walk `2.3e-5`；accel density `0.000875`、accel walk `0.000469` | `uav1/kalibr_imu_chain.yaml` 中相同 | **数值没有因 D430i 数据而更新**；它们不是 D430i 测量结果，gyro random walk 尤其仍是暂定值 |
| IMU 频率 | 组合输出 200 Hz；原始 gyro 200 Hz、accel 100 Hz | 旧配置记录 200 Hz；采集设置曾为 accel 63 Hz | 必须以各自驱动的实际发布频率为准，不能把插值合并频率理解成原始加计频率 |
| `T_body_imu` 平移 | 前方 0.040 m、上方 0.014 m、左右居中 | 相同 | D430i 文件沿用 D435i 安装值；尚未确认 D430i IMU 在机体中的实际位置与朝向 |

特别注意：当前 `d430i/body.yaml` 的矩阵数值沿用了 `uav1/body.yaml`。
导入器会固定写入 `source: measured Kalibr + body mounting`，这个文字不是测量
凭证；应按 D430i 实际安装重新测量并更新，不能因导入成功就把它当作实测值。
当前 D430i 的 IMU 内部校准状态也未证实；驱动曾提示采用默认 IMU 内参/外参。
30 分钟静止包还没有产生可替换上述噪声值的分析结果。

### 9.4 算法配置和启用状态

`estimator_config.yaml` 不是传感器测量结果。D430i 目录的该文件由导入器从项目
模板生成；旧 `uav1/estimator_config.yaml` 含有针对旧设备的项目配置和本地修改，
例如旧文件的 `num_pts` 为 300，而新生成文件为 150。切换前应逐项比较并确认
算法参数、线程数、话题映射和性能满足当前平台，不能把配置文件不同当成标定差异。

截至本文记录，D430i 标定包已生成，但 IMU 噪声和 `T_body_imu` 均待实测/确认，
硬件深度变换也仍需按实际模式核验；导入工具不会替用户切换 `calibration_dir`。
保持拆桨、关闭电机和 `flight_control: false`，先完成参数确认及台架验证，再单独
决定是否切换启动配置。
